# 字幕时间轴修整器

本地运行的字幕时间轴修整 Web 应用：Node.js + Express 后端，原生 HTML/CSS/JS 前端（无任何前端框架与构建步骤）。

## 功能

- **导入 SRT**：点击「导入 SRT」选择文件，或直接把 `.srt` 文件拖入页面；导入时自动规整（排序、负起点归零、补足最短时长、后移重叠块），保证初始状态合法
- **可缩放时间轴**：缩放滑杆 / ＋− 按钮 / `Ctrl+滚轮`（以光标为锚点）/「适应宽度」
- **拖动修整**：拖动任意字幕块的左/右边界调整起止时间，实时保证：
  - 每块时长 **≥ 500ms**
  - 相邻块间隔 **≥ 100ms**
  - 起点 **≥ 0**
- **整块平移**：按住字幕块主体横向拖动，时长保持不变：
  - 向左在 **0** 与**前驱 100ms 安全线**处夹取
  - 向右越过后继安全线时**递归推移**所有受影响的后继块（保持各自时长）
  - 同一次手势内先右推再左回拖，已被推开的后继**不自动回拉**；松手仅生成**一条**撤销记录
- **递归推移**：右边界越过后继安全线时，超出量递归推移所有受影响的后继块，且保持各块时长不变；向回拖动只释放空隙，不自动拉回后继
- **区间变速**：设置入点、出点与目标时长，将区间内及跨越边界的字幕按锚点（入点）做线性时间映射：
  - 文本与相对顺序保持不变，区间外字幕不被静默改写
  - 先「预览」（绿色高亮映射结果与目标区间）再「应用变速」，可随时「取消预览」或按 `Esc` 恢复原状
  - 映射后自动在受影响字幕内补足最短时长（500ms）并保证 100ms 间隔
  - 若约束只能依靠改动区间外字幕才能满足，不做任何修改，给出可点击定位的冲突提示
- **帧对齐**：选择 **23.976 / 24 / 25 / 29.97 / 30 fps** 并设置「单点最大允许偏移」（ms），对全部字幕起止点求落在帧边界上的全局最优方案：
  - 冲突时点与点**联动选择相邻帧**（动态规划全局求解，而非各自就近贪心），使所有点的**总绝对偏移最小**；总分相同取**整体较早**方案
  - 始终保持每块时长 **≥ 500ms**、相邻块间隔 **≥ 100ms**、起点 **≥ 0** 与原顺序
  - 先「预览」：逐条显示对齐前后时间码与起/止偏移（点击任一行定位该字幕），并汇总帧周期、受影响条数、总绝对偏移与单点最大偏移
  - 任一点超出容差或容差内无可行方案时**不修改任何字幕**，问题条目可点击定位；调大容差或先手动修整后重新预览
  - 「确认对齐」一次更新且**只生成一条撤销记录**；「取消预览」或按 `Esc` 恢复原状
- **读速校正**：设置**每秒最大字符数**（字/秒）与**处理区间**（入点、出点），按**去除空白后的 Unicode 字符数**计算每条字幕所需时长：
  - **不改文本、不改起点**，仅把读速过快的字幕终点向后延长，始终满足每块 **≥ 500ms**、相邻间隔 **≥ 100ms**
  - 延长造成的挤占**只在区间内递归后移后继**（各块时长不变），区间外字幕绝不移动；校正链越过区间出点或挤占区间外字幕时**整次预览失败**，列出可点击定位的冲突，不修改任何字幕
  - 先「预览」：逐条展示**校正前后读速（字/秒）、字数与延长量**（区间内参与处理的字幕青色标记，实际被延长/后移的绿色标记），并汇总处理条数、延长条数与**总延长量**
  - 「确认校正」一次应用且**只生成一条撤销记录**；「取消预览」或按 `Esc` 恢复原状；无需调整时确认也不会产生撤销记录
- **同步显示**：拖动过程中时间轴块、下方列表与状态栏实时同步显示文本与时间码
- **撤销**：「撤销」按钮或 `Ctrl+Z`，可撤销最近一次（及更早的）拖动、区间变速、读速校正与帧对齐
- **导出 SRT**：导出前再次校验约束，生成序号重排、格式合法的 `.srt` 文件下载

## 区间变速操作

1. 点击工具栏「区间变速」展开面板；默认填入当前选中字幕的起止（未选中时为整个时间轴范围），时间轴上以蓝色标出所选区间。
2. 修改**入点**、**出点**与**目标时长**：支持纯秒数（如 `3.5`）、`MM:SS,mmm`、`HH:MM:SS,mmm`。
3. 点击「预览」（或在输入框内按回车）：以入点为锚点把区间线性缩放到目标时长，绿色高亮显示映射后的字幕与目标区间，面板显示缩放倍率与受影响条数。
4. 确认无误点击「应用变速」（产生一条撤销记录）；不满意点击「取消预览」或按 `Esc` 恢复原状。
5. 若出现冲突（如变速后与区间外字幕间隔不足 100ms、区间外端点被新区间吞没），不会修改任何字幕：点击冲突条目即可定位到对应字幕，调整目标时长或出入点后重新预览。

## 帧对齐操作

1. 点击工具栏「帧对齐」展开面板，选择帧率（**23.976 / 24 / 25 / 29.97 / 30 fps**；23.976 与 29.97 按 NTSC 精确比率 24000/1001、30000/1001 计算帧周期）。
2. 设置**单点最大允许偏移**（非负整数毫秒，默认 20ms）：每个起止点只会吸附到距原值不超过该容差的帧边界。
3. 点击「预览」（或在容差输入框内按回车）：
   - 面板表格逐条列出**对齐前/对齐后的时间码**与起、止偏移（`+` 后移 / `-` 前移），点击任一行即在时间轴上定位该字幕；
   - 对齐后的字幕在时间轴与列表中绿色高亮；信息行汇总帧周期、发生移动的条数、总绝对偏移与单点最大偏移。
4. 确认无误点击「确认对齐」（一次性更新全部字幕，仅产生**一条**撤销记录）；不满意点击「取消预览」或按 `Esc`，现有字幕不做任何修改。
5. 若某点最近的帧边界也超出容差，或容差窗口内找不到满足 500ms 时长 / 100ms 间隔 / 起点 ≥0 的可行组合，不会修改任何字幕：面板列出可点击定位的问题字幕，调大单点最大允许偏移（或先手动修整时间轴）后重新预览。

## 读速校正操作

1. 点击工具栏「读速校正」展开面板；默认处理区间取当前选中字幕的起止（未选中时为整个时间轴范围），时间轴上以蓝色标出该区间。
2. 设置**入点**、**出点**（支持纯秒数如 `3.5`、`MM:SS,mmm`、`HH:MM:SS,mmm`）与**每秒最大字符数**（如 `15`，允许小数）。
3. 点击「预览」（或在输入框内按回车）：
   - 系统以「去除空白后的 Unicode 字符数 ÷ 字速上限」逐条计算所需时长（毫秒向上取整，至少 500ms）；起点与文本不变，只延长过快字幕；
   - 表格逐条列出**校正前/校正后的起止时间码、字数、前后读速（字/秒）与延长量**，点击任一行即在时间轴上定位该字幕；时间轴上区间内参与处理的字幕以青色标记、实际被延长/后移的以绿色标记；
   - 信息行汇总处理条数、实际延长条数与**总延长量**。
4. 确认无误点击「确认校正」（一次性应用，仅产生**一条**撤销记录；全部达标无需改动时不产生撤销记录）；不满意点击「取消预览」或按 `Esc`，现有字幕不做任何修改。
5. 若延长链会**越过区间出点**，或链尾与区间外字幕**间隔不足 100ms（挤占区间外字幕）**，整次预览失败、不修改任何字幕：面板列出可点击定位的冲突条目，扩大处理区间（把后继字幕纳入区间）、调大每秒最大字符数或先手动修整后重新预览。

## 一键启动（Docker）

单条命令启动（首次会自动构建镜像，依赖安装已纳入构建过程，无需任何额外配置）：

```bash
docker compose up --build
```

启动后访问 **http://localhost:3000**（容器内外均为 **3000** 端口）。

- 端口配置：`docker-compose.yml` 中 `"3000:3000"`，如需更换宿主机端口可改为如 `"8080:3000"`
- 唯一的服务端配置项为环境变量 `PORT`（默认 `3000`，见 `server.js`）；修改容器内监听端口时需同步调整 Compose 端口映射
- 数据全部在浏览器本地处理，无数据库、无外部服务、无额外配置文件

## 本地启动（无 Docker）

```bash
./start.sh          # 自动安装依赖并启动；等价于 npm install && npm start
```

同样访问 http://localhost:3000 。可用 `PORT` 环境变量改端口：`PORT=8080 npm start`。

## 项目结构

```
├── server.js            # Express：托管静态页面 + /api/health
├── public/
│   ├── index.html       # 页面结构
│   ├── styles.css       # 样式
│   ├── engine.js        # 约束引擎（浏览器/Node 共用）：解析、导出、拖动约束、整块平移、递归推移、区间变速规划、读速校正规划、帧对齐全局规划
│   └── app.js           # 前端交互：时间轴渲染、拖动、缩放、撤销、区间变速预览、读速校正预览、帧对齐预览、导入导出
├── test/engine.test.js  # 引擎单元测试
├── Dockerfile           # 依赖安装纳入构建，CMD 直接启动
├── docker-compose.yml   # 一键启动
└── start.sh             # 本地一键启动（自动装依赖）
```
